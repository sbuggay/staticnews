For the general picture: the Xbox version of the game was leaked by Cyberleek - first the resources, then the game binary.

Because modern Xbox is very close to a Windows PC with some extra Xbox stuff, running the actual game code isn't hard, it's mostly about compatibility and graphics, plus the binary doesn't have any special DRM/obfuscation.

The current projects (xcl and VIctory) basically take a Wine-like approach. The main problems they have to solve, as I understand:

- The game ships with raw RDNA 2 shaders, so the projects have to translate that to another format, e.g. DXIL for DirectX 12, and compile those shaders. So you need a good translation/recompilation pipeline, if it's bad, the shaders will be bloated and perform poorly

- Xbox has unified memory, while most PCs do not, so you have to add a lot of workarounds and book-keeping for the game to work properly with that

- Xbox's DirectX 12 differs from the normal Windows one in some ways, and the game uses Xbox-specific texture formats with DirectStorage

I just wanted to share this because there's a lot of misconceptions going around about this being a "recomp" or something like that. Decompiling the entire binary (it's about 100MB of real executable machine code) will be a much bigger effort than getting this binary to run.

If you want to use all available VRAM you need to fill it with bigger textures (which are usually the bulk of the data).
