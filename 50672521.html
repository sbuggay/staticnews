swozey|parent|next|

It's just an administrator/orchestrator for containers. If you start a docker container without kubernetes (docker/podman run) there's nothing to "orchestrate" it, as in if it crashes the kubernetes server restarts it, moves it to less loaded nodes, ties it to its storage, etc. You can even have it manage vms and other stuff.

This is assuming you know what a container is of course but you don't need to know cgroups or syscalls in depth to understand that k8s just keeps them running and moving around how you want.

It's a giant go api server in the end, "is nginx still running 3 containers? only one? start two more."
