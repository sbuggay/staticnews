The hardest thing to adjust to is the product pipeline moving from "let's fix the issues the most users face" to "we need to fix these issues, for this important customer".

Product led organizations often have a _very_ hard time adjusting to this, I personally recommend you carve out specific product and engineering teams for your effort, as getting into the backlog of consumer oriented product teams is going to completely torpedo any chance you have of closing big deals that depend on product changes. You really won't, and if you have goals that assume you will, you're already set to fail.

Have done small to medium institutional rollouts of Firefox in different orgs, some of which were on top of a Linux base and others a Windows base. Windows deployments include Firefox in the base image and configuration is managed with AD and Ansible. Linux deployments manage configuration with Ansible. The preinstalled browsers were removed or disabled.

All users received an orientation and were informed that Firefox is the only approved browser.

Firefox was pinned to the desktop and taskbar, usually with the name "INTERNET" as the web browser is commonly known here.

The number of support tickets was very small. Usually if a user reported a problem with the web browser, it was a page that was also broken in Chrome or some other network issue.

Users reacted positively when they saw that there are no ads in Firefox. uBlock Origin was preinstalled.

Without ads and tracking scripts the web browser is massively faster, which also was perceived by users.

If there is any initial resistance to Firefox, it usually melts quickly.

The only bother has been the frequent UI updates to Firefox, which occasionally cause frustration until we apply a new configuration to revert whatever fresh horrors Firefox designers have birthed. With ESR, these problems are less frequent.

I hope this Firefox Enterprise freezes the UI to the classic "tabs look like tabs" aesthetic, maintaining the option of vertical tabs.
