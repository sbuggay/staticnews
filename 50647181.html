The difference is that Microsoft is releasing a new fix, where the release of patch can be the first information to potential attackers; while Debian is re-releasing a fix that is known to attackers as soon as the upstream (e.g. kernel) has released it.

That changes things significantly. IIRC the recent data from major vulnerabilities like PHP2shell show that now attackers can go from seeing a patch to reverse engineering it; to finding the vulnerability; to making and testing an exploit; and actively applying it all within 1 hour or so. This means you can't wait for weeks to re-release a patch that has been released by others - you either have to keep the patch secret until you can apply it everywhere (as Microsoft does, and what coordinated disclosure of the PHP patch tried), or you have to redistribute all upstream fixes on the same day as the upstream provider does.

So going to predictable monthly releases is not something that Debian can do on its own - it can do it only if it coordinates it with e.g. Linux kernel and the other makers of key components and they agree to release their security patches on that schedule.
