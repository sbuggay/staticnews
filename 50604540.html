mjwsolo|parent|next|

Thanks for the question - it's a good one and you're mostly right. There's no seatbelt support today in localcode.

- File tools: reading or writing outside the project asks for approval.

- Shell commands: before a command runs it's parsed for the paths it mentions, and anything outside the project asks the same way. That only catches paths written in the command itself though, a script or python -c can still reach anything your user account can.

- So the prompts are a guard against mistakes, not a security boundary per se.

If you want a real boundary today, run localcode inside sandbox-exec or a VM.

Proper seatbelt support for shell commands is a good shout though, just created an issue for it https://github.com/mjwsolo/localcode/issues/254.
