I had the idea for BIGWORDS.PAGE when I wanted to display a message on a tablet that I had remote management control over, but no physical access. Configuring it to be a kiosk browser is easy, but how do I get the browser to show my message? So I made the URL be the message.

It uses a URL fragment to configure the message. Browsers don't send URL fragments to the server, so I never see your message. There's no backend, and no storage.

All parameters are documented, so generating a message link is easy. There's also a built-in editor to make it extra easy.

https://bigwords.page/#Hello,%20HN!&bg=ff6600&fg=000000&font...

There are a few extra features like slides, animations, and countdowns and timers. QR codes too. Not too fancy, but hopefully enough to be useful.

I know the uses for this are pretty niche. But it may be one of those things that you keep as a nugget in your brain, a tool in your back pocket. Not something you use often, but when you do it makes things just a little bit easier.

It's open source (MIT), and self-hostable if that's your thing.

Let me know what you think.

The highlights:

    The URL is the whole display: no accounts, no login, no backend.

    Nothing else: no lists, tables, links, quotes, images or rules.

    Underscores inside words are left alone, as in standard Markdown, so names like Home_Guest_5G, snake_case or first_name@example.com show exactly as typed. Only an underscore at a word boundary starts or ends emphasis.

    Code is shown exactly as typed. Nothing inside backticks is treated as formatting, a slide break, {countdown} or an escape, which makes it the easy way to show passwords and codes with symbols in them. A code span has to open and close on the same line. Browsers may write a typed backtick as %60 in the address bar; both forms work.

    All fonts ship with the site, each next to its license file. A font is only downloaded, from this site, when a display uses it.

    Screen wake: with wake=on (the default) the viewer asks the browser to keep the screen on. It asks again whenever the tab becomes visible. Browsers without support ignore it.

    The viewer can be embedded anywhere (OBS, dashboards); the editor and docs can't. HSTS is left to the TLS-terminating reverse proxy. The app reads all state from the URL fragment, so / serves every display. /editor and /docs are their own files (editor.html, docs.html); anything else is a real 404.

    img-src stays open because displays show images from any host. Inline styles are needed for the runtime @font-face rules and style attributes. A snippet, so 404 responses get these headers too.

    Exercises the canonical URLs, social cards and sitemap, which are only built when SITE_URL is set. The smoke test reads it too.
Don't get me started on the docstrings and code comments.
