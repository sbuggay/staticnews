Nice article. There's another option for pixel art that's recently been coming into vogue as tool usage improves in LLMs which is procedural graphics.

I actually experimented with creating a set of skills around rendering early AGI style EGA graphical scenes, and it worked surprisingly well.

So rather than storing full bitmaps, you instead store sequences of simple drawing instructions designed to recreate some specific scene - like you would an SVG.

As a result you end up sidestepping a lot of the problems with larger generative models, which can have issues with grid alignment, palette choices, and high-frequency noise.

They are used a lor, and modern edit models kind of support base cases - depth, canny, openpose - as a reference image. I mean they understand "ise image 2 as depth map", result indeed have same depth, etc. But interpretation sometimes arbitrary to model.

For the tasks where several control nets should be adhered (depth and canny abd segmentation) dreaded SDXL is still unmatched. SDXL also the only one handling influence weight for each control net normally, this ability completely vanished on modern models

Control nets in early post-SDXL models like ZIT or Flux kind of works, but still much worse in quality when combined. I suspect pure diffusion architecture of SDXL is really favorable to mixing control signals with precision, DITs probably can be trained to similar level for mixing signals but it is much harder. At least every post-SDXL model I tried is trained with single one in mind

This is all from personal expirience.
