PaulKeeble|root|parent|next|

By default a model comes at FP16, or 2 bytes per value and this is indeed Qwen 3.8 with 27Billion parameters, each of which takes 2 bytes by default so its about a bit bigger than 54GB for the model.

Most people are quantising it (reducing the size) and early tests on this model showed it retains pretty well down to about q4, or half a byte per parameter which is ~16GB or so. You also need space for context to get anything done, multiple GBs worth of it so you in practice can't really use Q4 on a 16GB card, 32GB allows the full 256k context.

These are compressing it down to 2 bits or even less per parameter on average, this means some parameters have more in places that matter with the goal of retaining as much as possible while shrinking it to fit on cards with less VRAM.

It's not quite that simple.

Local weights models might be outgunned by frontier cloud models, but my contention is that if you want to be actually relevant in the future, you have to have some instincts for all this stuff — some broad sense of how and why. When the labs people say "learn AI", a lot of them mean "learn our SaaS product" — learn a dependency.

I say, if you can run even the smallest local weights model (Gemma 4 E4B QAT, Nvidia Dory, Gemma 4 12B QAT, and up) you really should. Get a sense for what they can and can't do, run the whole stack, get Pi, understand how tool calling really works, write tools, etc.

This is a way to start building the core skills, or at least the footing for the core skills, that develops some cognitive independence.

One day very soon, I think, the talk of open weights will be much closer to practical, much closer to necessary, and I think being slightly further along in understanding is going to help.

And I say this as really a perpetual novice.
