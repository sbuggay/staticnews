RetroTechie|prev|next|

Bash me all you want, but after CPU, GPU, memory controller & a host of other things integrated in modern System-on-Chips (SoC), I've long held the belief that next logical step would be to integrate RAM.

Optimal: piecemeal. As in: X sockets on a board, each socket takes a chip that adds CPU core(s), GPU cores, and some amount of main RAM. More chips, more powerful computer.

Keyword: socket. Read: replaceable. Bad chip out, good chip in. Slow chip out, faster chip in. Soldered onto board = reliable, but a defect could junk the whole machine.


crote|parent|next|

Considering the current trend is for SoCs to deintegrate: don't count on it.

Putting RAM inside the logic die is crazy expensive - just look at how much footprint L3 cache takes up on a modern chip. It'll always make more sense to put it in a separate die, made using RAM-specific processes. With Zen the memory controller and GPU has (once again) moved to a separate die, and with X3D we're now even seeing separate cache dies.

There's of course HBM if you want to consider that "integrated", but the large cost bump, additional manufacturing risks, and loss of flexibility don't make that an attractive proposition unless you really need the extra speed. Regular DDR dies? You gain basically nothing by co-packaging those.


bartvbl|parent|prev|next|

Manufacturing processes for RAM and processor cores are not one and the same and use different tradeoffs. It's the main problem in-memory processing is running into, which is akin to what you're describing here. The die space required for the same level of performance makes the idea of on-die RAM intractible. The best they're able to do with RAM optimised manufacturing processes are tiny RISC-V cores that lack most of the feature sets. What apple does with moving the RAM chips on to the package really is the only viable option.

ACCount39|parent|next|

It is - anything short of HBM can be replaced that way.

The issue, of course, is just how much time, effort and skill is required to do it.

It might become a viable commercial process outside third world countries if RAM prices spike even more - or if someone finds a way to teach an off the shelf $1000 robot arm advanced autonomous microsoldering.

Then there's the problem of forcing the device itself to recognize the new RAM. It's a device-specific trick. RAM sticks have a little tag chip that tells a PC "how much RAM this stick has", but RAM chips themselves don't - so the device has to infer its RAM capacity from elsewhere. Like strap resistors on the board. Which you have to find and adjust for the new RAM capacity. That, or fix the RAM values in firmware, which is also device-specific.
