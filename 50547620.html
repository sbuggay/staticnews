I was involved with this project as a reporter, though others from my organisation did most of the work.

HN readers may be interested to know a bit about the tech stack. The 15 million or so documents, mostly Outlook mailbox exports, were provided to partners in the consortium via a tool called OpenAleph [1], which is maintained by DARC and based on ElasticSearch and a schema called FollowTheMoney [2], developed specifically for the investigative journalism use case. A lot of the original work on this was done by Friedrich Lindenberg (@pudo), who now runs OpenSanctions [3].

The timing was v. interesting given where we are with LLMs -- it's the first major leak I've worked on where it was possible to leverage local models to do some of the heavy lifting, and this only got more possible as the project went on. The coordinators provided a centrally hosted chatbot with RAG, but I also managed to get some surprisingly useful material using Qwen3.6-35B-A3B on my 24GB M2 MBA via a custom agent harness for Aleph/OpenAleph. [4]

Happy to answer any questions about techy stuff, though I'm not a spokesperson for the project by any means. Seen a few people saying "just release the data!", but I think that slightly misunderstands what this work is. The whole point of forming a consortium of hundreds of journalists and sifting through the dump is to identify the bits that are in the public interest to report on -- especially important in jurisdictions like the UK, where I'm based, which have very strong defamation laws. Think Panama Papers, not Wikileaks.

[1] https://darc.li/openaleph/ [2] https://followthemoney.tech/ [3] https://www.opensanctions.org/ [4] https://github.com/data-desk-eco/sift

I started off just running Qwen in hax [1], a minimal coding harness, and having it use the OpenAleph API to read documents (Aleph does OCR already), emails, etc. in a free-form session based on hypotheses I had -- kind of like a smart search engine, but context length was limited so these stalled early. I then used Claude to write a harness in Swift (CLI/menu bar app, see above) that uses one model session to queue a load of tasks for short follow-ups, followed by summarisation, which generated pretty useful Markdown reports on my queries, with links through to Aleph for the originals. These mostly related to the bank's involvement with the oil and gas industry (the focus of my research).

On the value prop of local models, it's very important with projects like these to have the data touch the absolute minimum number of machines, both for security against leaks and subpoenas as you say, but also to demonstrate responsible handling practices in case of legal pushback from the subject of the investigation.
