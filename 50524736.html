fuzzfactor|parent|prev|next|

I've been having a seamless dual-boot experience with Windows 11 and Linux Mint Debian Edition, LMDE7.

As a preface to those Mint instructions, in Windows Disk Management I shrink the main Windows partition by about 20GB to 50GB, this creates some new "unallocated space" immediately following the normal Windows C: volume.

Then create a "New Simple Volume" in that unallocated space, but do not assign a drive letter and do not format. This will be the sole Linux partition, no /swap, no /usr, none of that monkey business when you are not replacing Windows, merely adding Linux as an option to a "virtually unchanged" Windows PC. You want Linux to occupy a single partition just like Windows does. At the Command prompt in Windows Diskpart, next select the target HDD or SSD, then select the target Linux partition on that drive, and "SET ID=4F68BCE3-E8CD-4DB1-96E7-FBCAF984B709 which is the designator for Linux Root. Also in Diskpart you can select the EFI volume and assign an alphabetical letter to the EFI volume so you can see the hidden folders and back up the Windows-specific \EFI\Boot\bootx64.efi file contained within. Manipulating the "hidden" EFI files can only be done at the Command prompt (not the GUI) after assigning a drive letter like this, and after you reboot, that drive letter will be removed automatically and no more access to EFI unless you reassign a drive letter again in CMD.

Then boot to the LMDE7 USB drive so you can install Linux to the unformatted partition.

In the Mint install wizard you will have to choose the "Manual" partitioning & formatting option, which opens up infinite possibilities, but this simple dual-boot arrangement only takes a couple distinct settings. In the displayed list of partitions, select that unformatted volume as "root", indicated by the single slash "/", and choose to format it using ext2, ext3, or ext4. Then in the small fat32 boot partition (where the Windows boot files are already residing in the "hidden" \EFI\Microsoft\ folder), Do Not format this partition, but select it as the ideal location for the Linux boot files, and designate it as "/EFI/Boot".

That's it.

After completion, Linux will be completely independent from Windows. In the EFI boot volume there will be a new \EFI\debian\ folder alongside the \EFI\Microsoft\ folder. The only change to any Microsoft files (and it's a "big" one) is within the \EFI\Boot\ folder which is a common folder to all the OS's on that SSD. When first powered up, \EFI\Boot\ is the folder that the UEFI firmware searches for so it can execute \EFI\Boot\bootx64.efi which then boots the PC. On a plain Windows PC the bootx64.efi file is from Microsoft and points to \EFI\Microsoft\ then Windows boots normally. The Linux install process replaces bootx64.efi with a different bootx64.efi which points to \EFI\debian\ instead. This is also a good time to use Windows to back up the Debian-specific bootx64.efi file.

Fortunately, the Mint install process runs a Grub routine including os-prober, which as the name implies, probes for other OS's besides the Linux you are presently installing at the time. And auto-adds any OS's found, to the new Linux multi-boot menu. So it reliably picks up a regular Windows installation and adds an entry for that Windows to the Linux bootmenu. Basically that Windows bootentry points to the same old \EFI\Microsoft\ folder which is unchanged and then boots Windows normally when selected.

Unfortunately, os-prober has been commented out of the Grub files and the probe only functions upon OS installation. So when Grub itself is re-installed or updated at a later time, intentionally or not, os-prober no longer runs by default and Windows will be auto-removed from the Linux bootmenu and you wonder where it went. Windows is still there intact regardless and can be recovered by replacing the Linux bootx64.efi with the original Windows bootx64.efi that you backed up earlier. But that would give you no more menu access to Linux.

To avoid this deficiency in the default Grub files, in Linux you need to edit the \etc\default\grub file to uncomment (remove the # hashmark from) the GRUB_DISABLE_OS_PROBER=false line. This basically requires using sudo at the Linux command line since otherwise the file is read-only.
