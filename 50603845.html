kgeist|root|parent|prev|next|

The Bitter Lesson was first discussed around the time of the original GPT-3, and today's small local models vastly surpass GPT-3 despite having 10 times fewer parameters. It's true that if you just scale things up, they will automatically improve without any special effort. But that doesn't mean we shouldn't make any special effort or that we can't benefit from inference-time optimizations and training improvements.

Current models, including small ones, are trained on vastly more tokens and in vastly more simulated environments. So the Bitter Lesson still holds true here, but more for training than for inference.

Inference-time and architectural optimizations like MoE, quantization, compressed attention, looped transformers, multi-token prediction, Engram, etc., allow us to squeeze more out of the same hardware. It also looks like training models on code to make them more agentic has significantly increased their capabilities, i.e. training data quality matters just as much as scale.

I mean, the Bitter Lesson was true in the sense that you could just scale the same simple architecture (and train it on more data) without specializing and get better results. But the trend over the last few years has been the opposite, at least when it comes to inference (which matters most for local hosting): almost every new model introduces some specialization or optimization that allows it to run faster despite having more parameters. It's in AI labs' interest to save on hardware costs, so I don't think this trend will stop.

It’s true that you can get quants of some of these models running on cheaper hardware, but everyone should be realistic about the experience.

I’ve tried Qwen3.8-Flash-Next at quantizations that would fit in a system you describe (16GB VRAM and 64GB system RAM) and the experience is very different than what I get when I run larger quantizations on a 128GB unified memory machine.

These differences aren’t going to be obvious if you’ve only ever used the lower quants. There is a certain amazing feeling to getting a model running at all on cheap hardware, but there is a threshold where the quantization introduces enough subtle problems that the model spends extra time correcting and fixing things, if it can catch them at all.

There is a tipping point where running a smaller, less quantized model can be a better option, but you could be dropping speed even further.

Even where I can run Qwen3.8-Flash-Next at 5-6 bit quants, the model still has a large gap up to frontier models. Lately I’ve been letting it work on problems overnight (it’s cold and I need to heat the house anyway) to see what it can do. There have been many times where it takes millions of tokens to get a task done, but the result is incomplete and the code is painful to read. Then I have Opus 5.5 or even Sol 6.2 have a go at the same task and it’s done in 1/10th the tokens in 1/20th the time at a better quality. If I was running one of the smaller 2-3 bit Qwen quants the results would be even worse.

So come into this with some realistic expectations. It’s fun to run things locally as a hobby, but before dropping thousands of dollars on local AI everyone should do a reality check about what it can and cannot do. Even your $1000 minimum hardware budget would translate to a lot of months of a Claude plan. If privacy or independence are your only goals then this doesn’t matter, but for getting work done everyone should understand that local AI is not for saving money right now.
