You're mistaken. Here's a direct quote from Linux Torvalds dated 2006:

    The "version 2 of the License, or (at your option) any later version"
    language in the GPL copying file is not - and has never been - part of the
    actual License itself. It's part of the _explanatory_ text that talks
    about how to apply the license to your program, and it says that _if_ you
    want to accept any later versions of the GPL, you can state so in your
    source code.
    The Linux kernel has never stated that in general. Some authors have
    chosen to use the suggested FSF boilerplate (including the "any later
    version" language), but the kernel in general never has.
    In other words: the _default_ license strategy is always just the
    particular version of the GPL that accompanies a project. If you want to
    license a program under _any_ later version of the GPL, you have to state
    so explicitly. Linux never did.

Regardless of how you feel about using LLMs or using products that are developed with LLMs, it is a good idea to have an ecosystem of open source projects with differing levels of LLM involvement, including pristine software written entirely by humans.

The pragmatic argument for hard no-LLM projects: if models are to be useful, they need good input. Hand-written software that has been carefully audited is free from the kinds of feedback errors that will eventually weaken LLM code generation. Otherwise, a bad pattern gets copied. In the next generation, this bad pattern is seen a bit more often as stochastic models converge on it and more open source code adopts it. This is reinforced in the next generation and it becomes a common pattern. Then, in the next generation, this pattern is seen all over. This could be inert "non-coding DNA" like weird naming conventions or pointless comments. Or, it could be bad edge cases that become commonly exploitable.
