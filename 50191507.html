I've been working on something in a similar class for about a year called llcat

It came out of a lack of their being an LLM-native tool that feels like cURL or other unix-friendly things such as awk or sed.

I wanted a reference tool that was stateless, explicit, low-level, and composable without modal settings.

I couldn't find anything so I wrote it myself.

Instead of config files, llcat can index into files with built-in jq-syntax and line numbers. Then it can the save invocations for later. For instance

    llcat --save invocation.json \
      -k "@~/credentials.txt:12" \
      -u "@settings.json:.[3].host" \
      -s "@system_prompts:8" \
      -m "@settings.json:.[3].model" \
         "@query.txt:12" > output.txt
and then

   llcat --load invocation.json { ... parameters you want to override ... }
Conversations can be stored as JSON files and you can have a different input and output ones. This means you can do stuff like

   for i in *; do 
     cat "$i" | llcat --load settings.json -cr context.json  > ../results/"${i}.output"
     # or use attachments 
     llcat --load settings.json -a "$i" -cr context.json  > ../results/"${i}.output"
   done
And use a non-mutable conversation to apply the same context over a group of files.

One of my favorites is this pattern:

   llcat -k @~/secrets.json:.anthropic -u api.anthropic.com 
   llcat -k @~/secrets.json:.openrouter -u openrouter.ai/api
and so on...

Since there's no hidden state you can use it in shell scripts and get operational guarantees.

I've put a lot of effort into this and use it daily. If you can give it a go and give me feedback and file bugs, I'd love it.

https://github.com/day50-dev/llcat
