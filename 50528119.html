There has been a recent explosion in open source cad options.

fluidcad appears to be a remarkably good option now - particularly for something that only started development about a year ago.

I have used freecad, solvespace and onshape for at least a hundred hours each to make some reasonably complex parts. fluidcad resolves pretty much everything I found painful about those options.

I have some more limited experience with build123d which is also nice, but just not as easy and interactive as fluidcad.

Fluidcad provides normal interactive 3d cad interface with tools like extrudes/revolves/sketches but explicitly generates code as an intermediate step to constructing geometry and the code can be edited and refactored easily.

The linking between the code and the gui works remarkably well in practice.

It’s far easier to manage parameters and constraints in fluidcad where they are written out explicitly and can be edited vs what happened in a gui-only interface like Onshape.

If you’re playing around with a semi-constrained sketch to understand kinematics onshape tends to “helpfully” add random constraints which is really annoying to identify and correct. In fluidcad everything is way more explicit and visible and clear.

I have only spent about 5 hours using fluidcad but it looks remarkably useful despite some minor rough edges. It’s pretty much exactly what I wanted onshape or build123d to be.

Solvespace is a really beautiful piece of software but quite limited. fluidcad has the same sort of nice vibes as solvespace but is way more powerful.

dagmx|root|parent|next|

CAD isn’t polygonal geometry be definition.

Polygonal geometry is harder for GenAI to do because it’s still largely diffusion based to look like an object and topology is just a polygonal projection over it. It’s roughly equivalent to the diffusion model generating the image inputs to photogrammetry (not quite but a trivialized explanation)

Meanwhile CAD is represented as a series of B-rep surfaces and operations. Both are largely more procedural and more akin to a programming language for models. Therefore it’s easier for an LLM to drive something towards an end result.

Then the CAD engines tessellator generates the polygons, but topology is not super important for CAD.

The best LLM CAD results I’ve seen even in academia are largely simplistic still though. The more data you put in , the better it’ll be able to match that but it’s sort of like giving it a very clear set of functions it can do to make something.

averynicepen|root|parent|prev|next|

The most recent examples of the state of the art are from the initial release of GPT Astra and later Opus 5.5, maybe one or two months ago. Blender has already had an MCP since early this year, but it wasn't until these models came out that they are now capable of spatial reasoning and spatial consistency to be able to create something in 3D.

The way it works is the same way all other agentic AI works - feedback loops, and an AI driving a computer. The AI creates a shape in Blender, then takes orthographic view screenshots so it can "see" what it did, double checks its work against what the goal is, fixes errors if there are any, and then repeats until done.

It is worth noting that using Blender creates mesh representation 3D models, and does not create the boundary representation 3D models used in CAD programs. But I don't see anything stopping the industry from creating a similar MCP or other AI-native interface for b-rep CAD programs.

You can find the latest examples on social media or Youtube if you search for keywords Astra, Opus 5.5, and Blender.

This is a notably different approach than many of the existing "text to 3D" or "image to 3D" generators, which train their own machine learning algorithm to output models. Those have also been getting better, but the latest in this field was Astra driving Blender.

zonkerdonker|root|parent|next|

Ill take a shot at answering. Im also an ME at a very AI forward company.

The hard part of mechanical design isn't really the CAD. Ask any long time professional mechanical design engineer, and I can almost guaruntee you that they will tell you that they can CAD up a design faster than they can think it. There are AI tools that can absolutely help with some of the more tedious tasks in the process (2D specification and tolerancing, part families and variants, texture tables etc). The difficult part of the job is synthesizing the massive number of variables and requirements and finding an optimal solution. Current models have been trained on all sorts of 3D, not just functional mechanical designs. AI doesnt know that a MIM steel part from vendor X can have a thinner wall thickness compared to a diecast steel part from vendor y, which would mean x grams of weight saving which cpuld be used to shore up a weak area on the other side of the part. It doesnt know that a sharp corner near an injection gate can cause porosity in some materials. It's not good at designing strong parts in general. It doesnt know that the ID team wants a specific surface on an user-facing surface which requires draft angle minimums relative to the mold parting direction. And, if you take the time to gather all that data and then type it all out for a model, you would spend twice as long writing everything down in plain language as it would take to just CAD it up yourself.

It can take months to gather all of these requirements piece by piece from all teams across the org (rf design, thermal, structural and FEA, aerodynamics, environmental ratings, safety, etc etc), and as the design matures things change as well.

For professionals with training in the tools, CAD as it is now is already the most optimal method of getting a design into the computer, and that was never really the hardest part of the process anyway.
