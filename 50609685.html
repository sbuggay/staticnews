noddybear|root|parent|next|

A normal transformer has N layers, all of which are run forward for each token. A looped transformer is a bit different. Instead of N layers, it has K. These K layers are then looped, such that the output (not a token) of the first run of these K are fed back into the start of the K layer block. This looping happens until a fixed-point is achieved (i.e another loop results in a noop). At that point, a token is sampled. This means that tokens get different amounts of compute, depending on how challenging they are.

HarHarVeryFunny|root|parent|prev|next|

I don't see any similarity.

Speculative execution goes hand in hand with branch prediction, and refers to speculatively executing the instructions that you think (based on branch prediction) will follow a branch before you get there, with the goal of keeping the execution pipeline full. If the branch prediction proves to be incorrect then you need to throw away those speculatively executed results and instead execute the instructions on the path that the branch actually took.

With a looped transformer, there is no speculation. You are basically choosing to put some layers in a loop rather than have them duplicated. For example if you previously had 6 layers A B C A B C then you could put (A B C) in a loop and execute the loop twice instead. There is no speculation here - you are always going to execute A B C A B C in either case. The benefit of using a loop is that by avoiding the duplication of layers you are avoiding duplication of parameters and so keeping the model smaller.

The thalamo-cortical loop refers to the connections in our brain between the neocortex and the thalamus, with the thalamus acting as kind of a patch panel that routes/loops activations back to different areas of the cortex.

The association cortex is that part of our cortex (brain) where activations originating from different sensory modalities come together, distinct from the sense-specific areas (visual cortex, auditory cortex, etc) where they are initially processed. This is what allows patterns/correlations across different senses to be recognized, such as lip-reading assisting with speech recognition.

I'm not aware of any transformer variants where different input modalities (text, audio, video) are processed separately, so it's all more like non-specific association cortex in that regard. There is not necessarily any advantage to initially processing different sensory inputs on their own before combining them - our brain probably just does this as a matter of plumbing - the bit of the cortex nearest to our eyes/optical nerve processes vision, etc.

HarHarVeryFunny|root|parent|next|

The motivation for the Transformer's stacked layers approach (as described by Jakob Uszkoreit whose idea it was) was linguist's sentence parse trees, where each layer of the Transformer corresponds to a layer/level of the parse tree.

The overall goal for what would become the Transformer was to create a new language modelling architecture that could take better advantage of the available parallel (GPU, etc) hardware, as opposed to RNNs which required sequential training of each time step. Uszkoreit's insight was that language is as much parallel as it is sequential, as can be seen from these parse trees where different branches (parts of the sentence) can be analyzed independently and in parallel, until they join together at a higher level.

So, this is why the Transformer consists of explicitly stacked layers, because it is mimicking the layers/levels of a parse tree.

The evolution (assuming this direction sticks) of the architecture to a looped vs pass-thru design could perhaps be thought as moving away from this original linguistic inspiration to more of a brain-like architecture, although in reality the motivation is probably more practical to reduce parameter count.

aurareturn|prev|next|

For those wondering what loop transformers are:

LLMs have layers of data, called weights. During inference, each layer gets computed once. Moving weights from HBM memory to the chip is a major bottleneck because to generate a token, you need to move an entire layer into the chip, compute once, move it out, move the next layer in. Hence, memory bandwidth has been the #1 bottleneck for inference.

A loop transformer optimizes this bottleneck. Instead of one layer being computed once, it will compute the same layer multiple times, increasing the model intelligence without relying memory bandwidth as much. Bandwidth is still important, but not as much anymore.

More intelligence is squeezed by using the GPU compute that is typically sitting idle during inference.


loubbrad|parent|next|

If I understand you correctly, I think you are incorrect.

Looped transformers allow models to do more compute in the forward pass for the same total parameter budget (e.g., required VRAM to store the model). This doesn't inherently optimize the memory bandwidth bottleneck. A simple way to see this is that if we reuse a layer during the forward pass, we still need to fetch its weights from HBM again, which incurs additional memory bandwidth usage.

The main advantage is more computation for a fixed parameter count and model-weight VRAM footprint, not more computation for a fixed HBM bandwidth budget.
