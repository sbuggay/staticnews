jatorre|prev|next|

Author here. This started as a 2 m² vegetable bed and got out of hand: 8 soil probes, a weather station, a camera, and a Rain Bird valve that I control through an old Android phone tapping its own app.

The part I found interesting: a fixed rules engine for watering kept being wrong in ways that needed context (forecast, last week's response, what the leaves look like). So an agent now runs every morning, reads the full history (4M readings, 62 MB in Iceberg), changes watering within hard limits, and logs what it expects to happen so it can check itself the next day.

Disclosure: the data side runs on LakehouseBox, which I'm building. The code is at github.com/jatorre/garden-lake. Happy to answer anything, including "why not Home Assistant."

krishanjarvis|prev|next|

One practical lesson with agents that control physical things: give them a small set of named actions with hard limits, such as 'water zone 2 for at most 10 minutes', instead of raw device access. Models sometimes misread a sensor value or repeat an action because they forgot they already did it. A log of past actions that the agent reads before every decision, plus a cap on how often each action can run per day, turns most of those mistakes into harmless no-ops. A plant can survive one bad guess but not a stuck valve.
