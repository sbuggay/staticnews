miki123211|parent|prev|next|

A web browser feels more amenable to AI than most other software projects.

You have great specs for prompting. You have great test suites that you can use as verification criteria. Literally all meaningful implementations of these specs are open source, baked into the weights to some degree, and have many people writing publicly about their internals. You aren't really designing your own features from scratch; a lot of your work is of the "this site doesn't work, please fix site" kind, and that, given decent enough tooling which browsers do have, is also relatively easy for AI to do.

This is very different from game dev for example, where you're working with an engine which hasn't been designed for headless operation from the outset, and your actual goal is max(fun), not max(correctness), which is a lot harder to quantify and requires taste, human testing and many shots on goal.

Sure, you still need human devs in charge to take care of the architecture, tech debt, code quality and such, you can't vibe code a truly great web browser, but those humans can be significantly accelerated by AI.

I know the Ladybird folks realize this and this certainly isn't news to them; Andreas seems plenty AI-pilled to me.

I think AI is what's finally going to break the web browser monopoly.

what do you mean by using 100MB? i kinda have performed tests on dozens of browsers, albeit primitive, i close everything, wait free system memory to settle down, and open the browser and go to a single page, then I measure free OS memory, then I repeat those steps of closing the whole browser (no other OS apps running, except for a shell measuring free memory) and reopening the browser and navigating to fixed site a few times until the free memory stabilizes (because after closing and reopening for the first time for example, the browser kinda seems to leak some resources that aren't promptly released after closing). this measurement is flawed because it is not correctly measuring shared libs, some may be in memory whereas some not, but anyway if a browser uses less than 500MB it is a great achievement already. just to note: ladybird uses more. maybe you're just saying the overall cost of an extra tab, something like that, so we're discussing different things. side note: a lot of webbrowsers that claim to be lightweight are not, at least RAM consumption wise. again: many different things can be said about exactly what is RAM consumption, because if you have a lot of browser tabs opened, my measure of the whole engine really doesn't matter so much, because a fixed cost of shared resources will be diluted at each extra tab you open.
