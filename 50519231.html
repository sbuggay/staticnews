miki123211|root|parent|next|

self hosted push has huge privacy implications (you need to be constantly connected and reconnect on every network handover, so this would let every app know exactly when you leave for work and when you come back).

It would also give every app location permissions in some cases (by detecting when you connect to open hotspots based on your IP).

Not to mention the battery life; having to reconnect 150 different TCP sessions every time you lose and regain coverage (which is quite often in some areas) would destroy battery life.

The correct design for push is what web browsers do. Make one user have one session to one server, with the user telling the app what server it should connect to and how to deliver their notifications. Connecting to hundreds of different servers for different users is a problem to be solved by the delivery service.

In principle, browsers could let you self host web push (I don't know if any of them actually do, but the standard does allow it).
