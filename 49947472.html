My first gut reaction to this was: Have you tried using a vision-language model?

I used to have an elaborate Home Assistant setup with tons of zigbee sensors here and there telling me if front door is not closed properly, if the rice cooker is left on (via current monitoring), if the garage door is left open (with a magnetic contact sensor), if window is left open, if the soil is dry, etc. I had to keep changing batteries of all these things and manage flaky Zigbee connections in the past.

More recently, I've found the absolute most reliable, ~zero-maintainence solution to be an LLM. Home Assistant already has an LLM plugin, you can wire it up to a local LLM if you want, and you can just feed it an image and ask "Is this garage door open or closed" and I found that to be much better for my sanity than changing batteries every 6 months and dealing with flaky sensors sending me false alerts.

I even found it useful for "Did the cat vomit on the floor" (if so notify me and pause the cleaning robot schedule) and "Do any plants look like they need attention"

For TFA's use case, if you already have a security camera facing front, you can just feed it that image and ask "Are the garbage bins out"

Also, if you're worried about cameras sending home images to the cloud, there are non-cloud options. (I use Unifi cameras and Home Assistant gets a RTSP stream over LAN.)

Yah, this is how I've solved this in my Home Assistant setup. My doorbell camera can see where I keep my bins when they're not out. We have three types of bins- a trash bin, a recycle bin, and two yard waste bins. Recycling and yard waste are picked up on alternate weeks, and I often forget which bins need to go out.

I have an automation that will grab an image from that camera and send it to the Anthropic API with a prompt describing where the bins are, and the color of each bin. The prompt comes back with JSON indicating which bins it can see. If it can see e.g. the yard waste bin, and it's time to take the yard waste bin to the curb, it will send me a notification.

It also reminds me when it's time to return them to their "resting" position after pickup- unless I already have.

Home Assistant orchestrates this all. I also have it hooked up to a "Bindicator"- a white 3D printed bin with a color-changing LED inside, controlled by an ESP8266 using ESPHome. When it's time to move the bin it lights up the color of the bin that needs to be moved. If I haven't moved the bins back after a day it turns orange to remind me.

Claude configured the automations for me via MCP but it's not particularly complicated. It's pretty reliable, though sometimes just because of where the doorbell camera is it can't clearly see the bins. If it can't make a ruling on the bin location it just falls back to notifying me so I will sometimes get a reminder I don't need.

> Or the bin’s precise location - how many fixed reference points would I need to triangulate it on a 2D plane?

Back in 2019 I worked for a company (in San Diego) that added UWB-based positioning to the 7 train line in NYC.

The code I wrote ran on what was basically a combined Raspberry Pi 3 compute module connected to a UWB device installed into the train's bonnet which would ping UWB devices set along the track side to determine the position of the train.

In most situations I could get a unique position based on only two beacons, but I had the benefit of the trains being on one of a limited number of fixed tracks which severely limited where they could practically be in space... well, assuming there hadn't been a train derailment.

The system didn't work in a 2D plane, though, our surveyed track data and track side UWB positions were all 3D encoded as ECEF coordinates.

In some situations depending upon track layout you needed more than 2 beacons to determine the correct position if you were just sampling single points in isolation, but since you're working with a continuous stream of changed positions as the train ran along the track at predictable speeds, you could pretty easily figure out which of multiple possibilities it had to be based on what came before even if you had potential multi-positional results for the current sample.

Of course, we would use as many of the track side beacons as we could see to strengthen confidence in the positioning, and the beacons were placed so we could generally see a good 4-6 of them most of the time.

Snow was the biggest challenge for the system, in a heavy thick snow the UWB signals bounce all over the place and you get severe multipath effects that can make it pretty difficult to determine which is the true line of sight signal for your time of flight calculations.

Fun job, I had to get certified to be able to walk the NYC train tracks because we installed a lot of the track side beacons ourselves, and I spent a lot of late nights doing live testing runs on trains that were empty other than a couple of people from our company and some MTA workers assigned to our test trains.
