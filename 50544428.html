Hey guys! After I tried to reintroduce Signals Reactivity state management (inspired by Angular and SolidJS) to the Python community with my reaktiv package, I like to go one step further to reimagine how Python Notebooks (Jupyter Notebook, Marimo, …) could look like, if Signals gets used as the core mechanism for reactive data pipelines.

The clue here: each cell in the spreadsheet represents a signals primitive under the hood! Say hello again to Signal, Computed, Effect, Linked and Resource!

So effectively you are using the spreadsheet interface as a canvas to model your business logic around these core primitives. Each cell represents a data pipeline execution.

I am working in the signal processing field and like seeing dense data and see how parameters changes and affects the outcome. I also always liked how spreadsheets used data as part of their UI instead of writing an UI on top of the data.

Hopefully some data folks appreciate what I have done here. :)

Combining Frontend Tech with Data Stuff in Python.
