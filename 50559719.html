For the curious, the generalized process of reordering and potentially rotating pages so that when printed and folded (and optionally gathered into signatures) is called impositioning. There is specialized software with a variety of options that will do this for an input document.

Bookbinder JS is a nice web-based tool that will do this for you too, though I'm not sure it covers the exact folding algorithm described in this article.

https://momijizukamori.github.io/bookbinder-js/


compiler-guy|parent|next|

Similarly, the term printers use for a sheet that has been printed after imposition is a "signature". Sometimes called a "sig" for short.

The result of the imposition here would be considered an "eight-up sig", because you get eight usable pages on one side.

Books and magazines are typically bound from several signatures.

ggm|prev|next|

Done properly, for a signature to work you need different in-page offsets from the binding point for the left and right faces of "outside" and the innermost "inside and outside" sheets: the thickness of the paper affects the folding and so affects the offset of the page edge from the actual paper edge after guillotineing.

I fell down this rabbit hole about 3 decades ago playing with the various postscript n-up tools, and looking at the outcome. I was working with an A3 printer and hitting alignment problems on 16 page signatures. I do not think I worked out how to fix it, other than heuristical sub-adjustments.

After 8 pages, the bend radius difference is probably 1-2mm so it's definitely visible.

meowvia|parent|next|

A fixed words-per-page number is hard because it swings a lot with type size, leading, margins, and how many headings or images break up the text. At 10pt with normal margins, each A6-ish page in this layout holds roughly 180-220 words of plain prose, but that's a rough guide, not a layout rule.

For the markdown editor idea, I'd find a per-section word count more useful than a single estimate: split the draft at headings, show the running count against the page it will land on, and flag sections that overflow. That way you keep the estimate tied to the actual text, and the preview stays honest when a heading or a short paragraph pushes content onto the next page.
