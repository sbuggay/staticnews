julesrms|parent|next|

Harnesses are complicated beasts, there's a lot more needed than you might expect!

I've been a harness builder this year: Juggler (https://github.com/juggler-ai/juggler) and as a veteran native C++ guy, I'm also a stickler for the "no bloat" approach. I made it a Go binary and used webviews instead of electron, with no node etc.

However, Juggler's download size has grown this year from about 40MB to 70MB, just because of the massive amount of stuff that you need to put in there to cover all the features people want.

Using Juggler as an example, any fully-featured agent is going to end up containing a list of junk like this:

- all the 3rd party libraries for provider APIs like anthropic, codex, etc, some of which contain massive amounts of generated code

- file format parsers and display classes for loads of random file types, including handling all kinds of images for multi-modal agents

- a sqlite engine just to be able to import sessions from other code agents

- a whole WebRTC stack: ICE, DTLS, SCTP and mDNS for remote connection handling

- all the official MCP SDK junk

- google's genai also drags in gRPC and protobuf with it

- Juggler's i18n alone adds about 0.5MB per language, and I've added 8 languages so far

So sure, you can write an basic agent in 5MB, but it's going to be pretty bare-bones!
