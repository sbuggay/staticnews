rvz|root|parent|next|

There is zero conflation. WASM does not isolate what you think it isolates as long as the application is running in a memory corruptible engine. Compiling something from C to WASM does not get rid of those C-style vulnerabilities in the guest (which is what attackers use to escape isolation in the first place). That is the main point.

In fact, you are believing that WASM solves all our isolation problems if something like Linux as the guest application (written in C) is running in the browser, when that is a further from the truth.

Put it another way: May people thought "microVMs" were "safe" until AI agents found both types of bugs in Linux (key point here) to escape KVM's "hardware isolation" that microVMs use.

It is even worse. WASM runs the entire application all in a single piece of linear memory and it doesn't even have basic protections (ASLR) to make it difficult for attackers to escape. Just because it runs in WASM, does not mean that the protections are guaranteed for all code, especially converted C/C++ code.

We are now in an era where AI agents are tearing apart C/C++ based code every day and there are no limits. Therefore that risk is not removed and it still exists regardless.
