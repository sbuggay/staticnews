I think both are real problems -

1. why should we trust the AI work? and

2. make me understand what the agent team did, while it spinned for hours

I think no 1 will be solved by N-version coding, keeping a population of replicas which provide differential testing on fuzzed inputs or prod data. This also helps no 2 - where execution diverges it can be a bug or a missing spec. Either fix code or fix spec. The reason I think N-version approach will win is that it is easier to code again the same app than to imagine code execution and its edge cases. Let real execution flesh out the divergences. It is easier than formal verification but still complex because it requires a careful setup where randomness, APIs, databases and other external state can be controlled for comparison.

OP said they use this question "What’s the cost that made this a bad idea, and is that cost still there?" to triage. In our case it is getting cheaper to spend tokens, N-version stops being too expensive. Having a population of replicas instead of a singleton would be the safe approach. It can even be faster, you can build the replicas in parallel, while test creation would take extra time on top of implementation. It's basically unbounded testing from input side. Makes performance optimization of one replica safer too.
