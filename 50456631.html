From the security page [0]

> Don’t use the emulator to test the following:

> - IAM policies and permissions boundaries

> - Resource-based policies, such as bucket policies

> - AWS KMS key policies

> - Access across AWS accounts or across AWS Regions

> - Any other security control

> Some services in the emulator evaluate IAM policies for IAM users and roles that you create in the emulator, but not the same way as AWS. The emulator never denies a request signed with its own key. It doesn’t check AWS KMS key policies or Amazon S3 bucket policies. It also doesn’t support calls across accounts or Regions. So a request that AWS denies might succeed in the emulator. A request that AWS allows might fail.

This is a shame because I'd love for the official AWS product to be better than e.g. ministack and localstack on this, which will go some of the distance. I think because the agents were only building on the public API surface, it's hard to build this part. But they should've tried and let the agents read whatever policy engines AWS has.
