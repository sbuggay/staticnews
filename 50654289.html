Yes, ribbon UI is essentially horizontal icons (some of which open submenus) so you can think of it as icon-based menu instead of text-based menu.

The issue with icons is that some of them are difficult to interpret (comparing to text menu where there's text explanation of what this option does).

More importantly, icons occupy more space than text menus so on each screen they only show a subset of functions available, based on their understanding of what the user might need a this point. So it is context-based; when you switch between editing a text paragraph, editing a table, and editing an image, or embedded object, you will be shown different icons in the ribbon. Yes, it can save time when you perform some basic tasks, but it can be significant disadvantage if you need to access some obscure function. With text menu all options are always available to you, while with ribbon you will have to guess where this action is (which icon represents it) and if it's not available in the ribbon how do you access it.
