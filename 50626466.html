The article says “This means that for P to equal NP, there must be some trick to computing permanents using AND/OR/NOT on the bits of the input that is better than addition and multiplication.”

This is implying that if P=NP then there must be a polynomial time algorithm for finding the permanent. But that isn’t known to be true. It would be consistent with all known results if P=NP but computing the permanent is still not possible in polynomial time.

Finding the permanent of a 0/1 matrix in polynomial time is stronger than P=NP; it would let you count the number of solutions to NP problems in polynomial time.

Gabriel54|parent|next|

It wouldn’t. If P=NP then many problems we think are hard (ie currently require exponential time) would in fact be solvable in polynomial time. But such a polynomial time algorithm might be “galactic” in the sense that the constants are so astronomically large that in practice the algorithm would not be faster than current methods.

Note that this is not widely believed to be likely, because usually if a problem is in P, then usually further work can improve constants considerably, but it is a possibility that there is a certain class of problems in P that are “galacticly” polynomial.

inkysigma|parent|prev|next|

Depending on the proof of P=NP and what you mean by "easily". In TCS, anything polynomial is considered "easily" so it could easily be the case that some ridiculous polynomial is implied with some ridiculous constants.

Suppose the proof of P=NP were not constructive, then Levin's universal search algorithm automatically gives us an algorithm that finds the factors in polynomial time. This would satisfy some definition of "easily" from above. However, if you take a look at Levin's universal search, it quickly becomes apparent the constants involved are truly galactic and not worth even thinking about in a practical sense.

If the proof of P=NP were constructive but gave some incredibly high degree polynomial or something with incredibly high constants, then we might be more wary. We would be able to get factors in polynomial time but it would still be "hard" in a practical sense to get the private key but it becomes exceedingly difficult to guarantee that there isn't some practically efficient algorithm. Proving fine grained lower bounds like this has been difficult to say the least.

If the proof of P=NP were constructive and efficient, then we would easily be able to get the private key. There is some additional detail here about what NP complete problem was actually solved (and thus how much the polynomial reduction cost but this is typically small) but this is a bit detailed and unclear. We would also probably begin searching for a directly efficient factoring algorithm.
